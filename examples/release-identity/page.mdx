# Release identity

Resolve the canonical Git tag and GitHub Release name for the root package:

```sh
npm exec -- workspace-release-identity . --pretty-json
```

Resolve a typed Restore Release source:

```sh
npm exec -- workspace-release-identity restore-source \
  'run:37624987179' \
  --repository moyarich/workspace-tools \
  --pretty-json
```

The accepted source types are:

```text
commit:<sha>
tag:<tag>
run:<run-id>
artifact:<artifact-id>
github-url:<supported-github-url>
```

A GitHub Release URL is also accepted through the explicit `github-url:` form:

```sh
npm exec -- workspace-release-identity restore-source \
  'github-url:https://github.com/moyarich/workspace-tools/releases/tag/%40moyarich%2Fworkspace-tools%400.1.0' \
  --repository moyarich/workspace-tools \
  --pretty-json
```

The output includes the source kind, resolved kind, normalized source value, and exact full commit SHA.

## Verify published-artifact equivalence

When exact source provenance is unavailable, compare the candidate commit with the immutable package already present in a registry:

```sh
npm exec -- workspace-release-identity restore-equivalence . \
  --commit 8b4539e214afc9d87dfbad3e52243e4426c26179 \
  --registry https://npm.pkg.github.com \
  --pretty-json
```

You can repeat `--registry` for multiple published copies. A match from any supplied published registry proves artifact equivalence; other mismatches or lookup failures remain visible in the result.
