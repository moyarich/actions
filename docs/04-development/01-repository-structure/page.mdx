# Repository structure

This repository owns **Workspace Tools' command-line implementations and npm package**. The separately maintained [reusable-workflows](https://github.com/moyarich/reusable-workflows) repository owns reusable GitHub workflows and composite actions that invoke these commands. Do not describe or maintain those workflow implementations as if they live here.

```text
apps/playground/          # documentation/example presentation application
docs/                    # source documentation and maintainer guidance
examples/                # copyable CLI usage examples and explanations
src/
  discover-packages/
  dependency-check/
  issue-dependency-tree/
  package-lock/
  publish/
  release/
  release-identity/
  sim-version-resolver/
  workspace/             # shared workspace/package utilities
tests/                   # Vitest tests grouped by capability
dist/bin/                # committed, generated executable .mjs bundles
vite.cli.config.ts       # CLI bundle configuration
package.json             # npm exports, bin map, scripts, and publish configuration
.github/workflows/       # this repository's callers of reusable workflows
```

## Responsibility boundaries

- `src/<capability>/*` holds implementation and CLI entrypoints. Share behavior through feature modules, not workflow shell fragments.
- `tests/<capability>/*` tests behavior. Run `npm test` before proposing changes.
- `dist/bin/*.mjs` is generated by `npm run build` and intentionally committed. Every public command must appear in the `bin` map in `package.json`.
- `docs/` is authoritative guidance; `examples/` contains runnable CLI examples. `apps/playground/` presents them rather than maintaining divergent copies.
- `.github/workflows/` contains repository-local automation. Shared workflow implementations, GitHub Actions and their contracts belong to [moyarich/reusable-workflows](https://github.com/moyarich/reusable-workflows).

Do not add `src/actions/`, `actions/`, `dist/actions/`, or `reusable_*.yml` to this repository just to mirror reusable-workflows. They are not part of the current Workspace Tools layout.

## CLI build and package

From the repository root:

```sh
npm ci
npm test
npm run build
npm pack --dry-run
```

`npm run build` builds the CLIs using `vite.cli.config.ts`. The published npm tarball includes `dist/bin` via `package.json#files`, not the development sources, docs, tests, or playground. `npm pack --dry-run` is the easiest way to inspect the publishable file list.

The eight declared npm executables are:

```text
discover-packages
issue-dependency-tree
sim-version-resolver
workspace-dependency-check
workspace-package-lock
workspace-publish
workspace-release
workspace-release-identity
```

Only command paths declared in `package.json#bin` are installation entrypoints. An extra generated file under `dist/bin` is not automatically a published command.

## Committed distribution

`dist/bin/` is tracked intentionally so a checked-out Git revision has its matching executable builds. After changes to `src/` or the CLI build configuration, run `npm run build` and commit the resulting `dist/bin/` differences. The `check-dist.yml` CI job rebuilds and compares the committed bundles, and fails if they are stale.

`self-heal.yml` can regenerate formatting, lockfile, and dist changes on a branch, but a passing **CI run at the latest commit** remains the verification boundary. Do not assume that an earlier passing run covers later self-healing commits.

## Local and shared workflows

```text
.github/workflows/
  check-dist.yml         # manual committed-distribution validation
  ci.yml                 # package tests, dry-run pack, dist verification
  self-heal.yml          # repository maintenance / regenerated output
  pages.yml              # playground deployment
  release-draft.yml      # release draft preparation
  release.yml            # package release preparation
  publish.yml            # publish to selected registries
  reset-release.yml      # guarded release reset
  restore-release.yml    # guarded historical recovery
  delete-release-tag.yml # explicit release/tag cleanup
```

Local `uses: moyarich/reusable-workflows/.github/workflows/...@main` jobs consume the shared workflow API. If an input or source selector changes, verify **both** the caller here and the `workflow_call.inputs` contract in reusable-workflows. Prefer versioned action/workflow references for downstream users who need reproducible behavior.

## Workspace Tools sources for reusable workflows

- **`registry`** installs a published Workspace Tools version from public npm (`registry.npmjs.org`). This is the normal choice for other repositories; it requires no GitHub Packages read grant.
- **`workspace`** builds the CLI from the checked-out `@moyarich/workspace-tools` repository. This repository's release, publish and draft callers use it to test local source.
- **`repository`** obtains and builds Workspace Tools from an explicit Git ref; useful for unpublished changes but slower than a pinned npm installation.

The source selector is about **where the CLI comes from**, not where a consumer's package will be published. Publishing destinations are separately controlled with `registry: npm | github | all`.

## Dependency and architectural boundaries

Workspace Tools provides low-level automation used by other repositories. Its library/CLI code must not depend on MoyaForge or the consumer application it is automating. The playground is a presentation application and must not become a dependency of the shipped CLI.
