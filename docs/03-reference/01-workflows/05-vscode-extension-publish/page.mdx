# VS Code Extension Publish

Use `reusable_vscode-extension-publish.yml` for the CI/CD publishing path for extension repositories.

The workflow provides these release safeguards:

- dry-run is the default;
- real publishes pass through a protected release environment;
- the requested version must match `package.json`;
- the canonical `v<version>` tag is verified by default;
- the matching GitHub draft release is verified before publication;
- the workflow packages and retains the VSIX artifact;
- Marketplace publication happens before the GitHub draft is promoted;
- `already-published` mode supports recovery when the Marketplace version already exists;
- the workflow summary records version, tag, artifact, Marketplace state, and GitHub Release state.

## Example

```yaml
jobs:
  publish:
    uses: moyarich/workspace-tools/.github/workflows/reusable_vscode-extension-publish.yml@v0.1.0
    with:
      target-branch: ${{ inputs.target-branch }}
      dry-run: ${{ inputs.dry-run }}
      version: ${{ inputs.version }}
      marketplace-mode: ${{ inputs.marketplace-mode }}
    secrets:
      vsce-pat: ${{ secrets.VSCE_PAT }}
```

For a monorepo extension, set `extension-directory`. Validation commands and additional `vsce package` arguments are inputs so callers can preserve extension-specific checks without copying the workflow.

The caller should normally own the trigger, concurrency policy, and repository-specific display names. The reusable workflow owns publishing mechanics and release safety checks.
